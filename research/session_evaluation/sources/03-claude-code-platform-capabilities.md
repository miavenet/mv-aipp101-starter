# Claude Code Platform Capabilities for Session Evaluation at Compaction Time

**Source:** Claude Code docs fetched from code.claude.com/docs (hooks.md, sessions.md, checkpointing.md)

## Quick Reference: What Hooks Can/Cannot Do at Compaction

| Capability | Supported? | Source |
|-----------|-----------|--------|
| **PreCompact hook can block compaction** | Yes (exit code 2 or `"decision": "block"`) | https://code.claude.com/docs/en/hooks.md#precompact |
| **PreCompact receives trigger (manual/auto)** | Yes | https://code.claude.com/docs/en/hooks.md#precompact-input |
| **PreCompact receives custom_instructions** | Yes (null for auto) | https://code.claude.com/docs/en/hooks.md#precompact-input |
| **PreCompact can inject additionalContext into compaction summary** | No (discarded) | https://code.claude.com/docs/en/hooks.md#precompact |
| **PostCompact receives summary text** | Yes (`compact_summary`) | https://code.claude.com/docs/en/hooks.md#postcompact-input |
| **PostCompact can block or influence compaction** | No | https://code.claude.com/docs/en/hooks.md#postcompact |
| **SessionStart with source "compact" can inject additionalContext** | Yes | https://code.claude.com/docs/en/hooks.md#sessionstart-decision-control |
| **Prompt/Agent hooks available on PreCompact/PostCompact** | No (command/http/mcp_tool only) | https://code.claude.com/docs/en/hooks.md#prompt-based-hooks |
| **Async hooks can block or control decisions** | No (async hooks don't block) | https://code.claude.com/docs/en/hooks.md#run-hooks-in-the-background |
| **Hook can programmatically trigger /clear** | No | https://code.claude.com/docs/en/hooks.md (no mention of command dispatch) |
| **Hook can start new session programmatically** | No | https://code.claude.com/docs/en/hooks.md (no mechanism documented) |

## 1. PreCompact Hook: Blocking and Input

**URL:** https://code.claude.com/docs/en/hooks.md#precompact

**Exit Code 2 to Block:**
> "Exit with code 2 to block compaction."

**Alternative Decision Format:**
> "You can also block by returning JSON with `"decision": "block"`."

**Effects of Blocking:**
> "Blocking automatic compaction has different effects depending on when it fires. If compaction was triggered proactively before the context limit, Claude Code skips it and the conversation continues uncompacted. If compaction was triggered to recover from a context-limit error already returned by the API, the underlying error surfaces and the current request fails."

**Input Fields (PreCompact input section):**
```json
{
  "session_id": "abc123",
  "transcript_path": "/Users/.../.claude/projects/.../00893aaf-19fa-41d2-8238-13269b9b3ca0.jsonl",
  "cwd": "/Users/...",
  "hook_event_name": "PreCompact",
  "trigger": "manual",
  "custom_instructions": null
}
```

**Trigger Values:** `"manual"` for `/compact`; `"auto"` for auto-compaction reaching the auto-compact window.

**Custom Instructions:** "For `manual`, `custom_instructions` contains what the user passes into `/compact` and is `null` when they pass nothing. For `auto`, `custom_instructions` is `null`."

**stdout/additionalContext Influence:**
> "Claude Code discards a PreCompact hook's `systemMessage` and `continue` fields."

→ **PreCompact stdout/additionalContext cannot influence the summary text itself.**

**Timeout:** Default 600 seconds (common field default; https://code.claude.com/docs/en/hooks.md#common-fields).

**Async Hooks:** Cannot block. Async hooks run in the background and cannot return decision control (https://code.claude.com/docs/en/hooks.md#run-hooks-in-the-background).

## 2. PostCompact Hook: Input and Output

**URL:** https://code.claude.com/docs/en/hooks.md#postcompact

**Input Fields:**
```json
{
  "session_id": "abc123",
  "transcript_path": "/Users/.../.claude/projects/.../00893aaf-19fa-41d2-8238-13269b9b3ca0.jsonl",
  "cwd": "/Users/...",
  "hook_event_name": "PostCompact",
  "trigger": "manual",
  "compact_summary": "Summary of the compacted conversation..."
}
```

**compact_summary Field:** Yes, "The `compact_summary` field contains the conversation summary generated by the compact operation."

**Decision Control:**
> "PostCompact hooks have no decision control. They can't affect the compaction result but can perform follow-up tasks."

**stdout Handling:** "Shows stderr to user only" (https://code.claude.com/docs/en/hooks.md table on exit codes).

**Discarded Fields:**
> "Claude Code discards a PostCompact hook's `systemMessage` and `continue` fields."

→ **PostCompact cannot inject additionalContext back into the session.**

**Timeout:** Default 600 seconds.

## 3. SessionStart with source "compact": Re-injecting State After Compaction

**URL:** https://code.claude.com/docs/en/hooks.md#sessionstart-decision-control

**source Field Values:**
> "How the session started: `"startup"` for new sessions, `"resume"` for resumed sessions, `"clear"` after `/clear`, `"compact"` after compaction, or `"fork"` for a new session forked from an existing one."

**additionalContext After Compaction:**
> "`additionalContext`: String added to Claude's context at the start of the conversation, before the first prompt. See [Add context for Claude](#add-context-for-claude) for how the text is delivered and what to put in it."

**Is This the Documented Way?**
Yes. SessionStart with `source: "compact"` is the documented mechanism to inject state after compaction. The hook receives the compaction has occurred and can return `additionalContext` as a JSON field that Claude will see.

**Important Limitation:** "Applies when `source` is `"startup"`, `"resume"`, or `"fork"`; ignored on `"clear"` and `"compact"`." → **sessionTitle is ignored on compact, but additionalContext is not explicitly listed as ignored.**

→ **additionalContext is supported on source "compact"; it is the official way to re-inject state after compaction.**

## 4. Other Hook Types for Evaluation

**URL:** https://code.claude.com/docs/en/hooks.md#how-prompt-based-hooks-work

**Prompt Hooks (`type: "prompt"`):**
- Supported events for prompt hooks: `PermissionDenied`, `PermissionRequest`, `PostToolBatch`, `PostToolUse`, `PostToolUseFailure`, `PreToolUse`, `Stop`, `SubagentStop`, `TaskCompleted`, `TaskCreated`, `TeammateIdle`, `UserPromptExpansion`, `UserPromptSubmit`.
- **NOT supported on PreCompact, PostCompact, SessionStart, or SessionEnd.**
- Default timeout: 30 seconds; 10 seconds on UserPromptSubmit.
- Response schema: `{ "ok": true/false, "reason": "...", "impossible": true/false }`.
- Behavior on `ok: false` varies by event. On `Stop`: reason is fed back to Claude; turn continues unless `impossible: true`.

**Agent Hooks (`type: "agent"`):**
- Same event support as prompt hooks (excludes compaction events).
- Default timeout: 60 seconds.
- Spawns a subagent with Read, Grep, Glob access.
- Response: `{ "ok": true/false, "reason": "..." }` (no `impossible` field).

**Key Limitation for Evaluation:**
> "Events that support `command`, `http`, and `mcp_tool` hooks but not `prompt` or `agent`: ... `PostCompact`, `PreCompact` ..."

→ **Prompt and agent hooks cannot evaluate at compaction time. Only command/http/mcp_tool hooks work on PreCompact/PostCompact.**

**UserPromptSubmit Hook:**
- Signature: runs before Claude processes a prompt.
- Can use `prompt` or `agent` type.
- Response behavior: on `ok: false`, turn ends and reason appears as warning line; with `continueOnBlock: true` (prompt only), reason is sent to Claude and turn continues.

→ **No hook type can directly inject a warning to the user or model that compaction is about to happen; PreCompact runs but can only exit 2 or return `"decision": "block"`, not inject additionalContext.**

## 5. Transcript Format and Contents for Evaluation

**URL:** https://code.claude.com/docs/en/sessions.md#export-and-locate-session-data

**JSONL Format Stability:**
> "The entry format is internal to Claude Code and changes between versions, so scripts that parse these files directly can break on any release. To build on session data, use `/export` or the [script interfaces](#access-conversations-from-scripts) instead."

→ **Transcript JSONL format is NOT documented as stable; changes between versions.**

**Documented Contents:**
> "Each line is a JSON object for a message, tool use, or metadata entry."

**Specific Markers Documented:**
- "Summarized conversation" marker appears in the conversation where compressed messages were (https://code.claude.com/docs/en/checkpointing.md#rewind-and-summarize).
- Compaction replaced the cached conversation (PostCompact uses `compact_summary` field).
- No explicit "isCompactSummary" or boundary marker documented in JSONL; checkpoint markers are only in the UI.

**Access Recommendations:**
> "To build on session data, use `/export` or the [script interfaces](#access-conversations-from-scripts) instead."

- `/export`: "The interfaces below produce structured data for a script to parse: a JSON result from a run, the path to a session's transcript file, or a live stream of events."
- `claude -p --resume <session-id> --output-format json <prompt>`: structured JSON output.
- Hooks receive `transcript_path` (absolute path to the JSONL file).

→ **Internal JSONL format is undocumented and unstable. Evaluators should use `/export` or JSON output from `claude -p`, not parse JSONL directly.**

## 6. Mechanisms for Starting Over or Branching

**URL:** https://code.claude.com/docs/en/sessions.md

**`/clear`:**
> "start fresh with an empty context. Claude Code saves the previous conversation; resume it with `/resume`, or, in the same Claude Code process, from [the rewind menu's previous-session entry](/docs/en/checkpointing#rewind-past-a-cleared-conversation)."

- Starts a new session; previous conversation is saved and resumable.
- If you pass a name, the old session gets that name; new session starts unnamed.

**`/rewind` + Checkpoints:**
> "Claude Code automatically tracks Claude's file edits as you work, allowing you to quickly undo changes and rewind to previous states."

- Checkpoints capture state before each turn.
- `/rewind` menu offers: restore code and conversation, restore conversation only, restore code only, summarize from here, summarize up to here.
- **File changes by Bash commands are NOT tracked.** Subagent edits are NOT restored unless the subagent is a foreground forked skill.
- **Symlinked/hard-linked files are NOT restored.**

**`/compact [instructions]`:**
> "replace history with a summary, optionally focused on what you specify."

- Compresses conversation into a summary, preserving code and later messages.
- The `/compact` command can take custom instructions to guide the summary.

**`--resume / --continue`:**
> "Reopens the most recent conversation in the current directory" (`--continue`) or opens picker (`--resume`).

- Resumes a saved session without creating a new one.

**`--fork-session` (with `--resume` or `--continue`):**
> "Branch a session: Branching creates a copy of the conversation so far and switches you into it, leaving the original intact."

- Creates a new session ID with copied transcript; original unchanged.
- From CLI: `claude --continue --fork-session` or `claude --resume <name> --fork-session`.
- From within session: `/branch <name>`.

**`/export`:**
> "Run `/export` to open a menu that lets you copy the current conversation to your clipboard or save it as a plain-text file, with messages and tool outputs rendered as readable text."

- Exports rendered transcript for reading.
- `claude -p --resume <session-id> --output-format json <prompt>` produces structured JSON.

**`claude -p` (Headless/Programmatic):**
- Non-interactive mode. Can run an evaluator prompt over a transcript.
- `claude -p --resume <session-id> --output-format json "summarize changes"` outputs JSON result.
- `--no-session-persistence` suppresses writes; no transcript created.

**Hooks Triggering Actions:**
> "Can a hook trigger /clear or start a new session programmatically?"

**Answer: NOT DOCUMENTED.** Hooks receive event data on stdin and return JSON on stdout. No mechanism exists to trigger commands like `/clear` or spawn a new session from a hook's JSON response. Hooks cannot directly invoke session commands.

## 7. Official Guidance on `/clear` vs `/compact` and Auto-Compact Settings

**URL:** https://code.claude.com/docs/en/best-practices.md (referenced), https://code.claude.com/docs/en/sessions.md#manage-context-within-a-session

**When to Use Each:**
> "Manage context with skills and subagents / Beyond compaction, you can use other features to control what loads into context ... **Skills** load on demand ... **Subagents** work in their own context window."

**General Guidance (from sessions.md):**
> "For how compaction interacts with CLAUDE.md, skills, and rules, see the [context window guide](/docs/en/context-window). For strategies on when to clear versus compact, see [Best practices](/docs/en/best-practices#manage-your-session)."

**Referenced but Not Quoted:** Best practices page at https://code.claude.com/docs/en/best-practices.md#manage-your-session (exists but specific guidance not fetched in detail here).

**Auto-Compact Settings:**
- `autoCompactWindow`: set token threshold for auto-compaction (https://code.claude.com/docs/en/settings-reference.md).
- `autoCompactEnabled`: boolean to enable/disable auto-compaction.
- `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`: percentage override for auto-compact threshold.
- `CLAUDE_CODE_AUTO_COMPACT_WINDOW`: environment variable to set absolute token window.
- `/autocompact <value>`: command to set the window.

**Documented Distinction:**
- `/clear`: start fresh; previous conversation saved.
- `/compact`: replace history with summary; keep code and later messages.
- Auto-compact: triggered when conversation reaches the auto-compact window threshold; cannot be blocked except via PreCompact hook.

→ **Official guidance exists but is cross-referenced; specific "when to clear vs compact" details are in https://code.claude.com/docs/en/best-practices.md#manage-your-session (not fully fetched here).**

## Key Findings for Session Evaluation Workflow

**Best-Documented Path for Evaluation:**

1. **Evaluate at compaction time:** Use a **PreCompact hook** (command type) that:
   - Reads `transcript_path` (JSONL, but undocumented/unstable format).
   - Reads stdin JSON (includes `trigger`, `custom_instructions`, `session_id`, `cwd`).
   - Exits code 2 to block, or returns `{ "decision": "block" }`.
   - Cannot inject additionalContext into the summary.

2. **Re-inject state after compaction:** Use a **SessionStart hook** with `source: "compact"` that:
   - Returns `{ "hookSpecificOutput": { "additionalContext": "..." } }` to inject state.
   - Sees the compaction has occurred (source field value).
   - Runs after compaction completes.

3. **Avoid:**
   - Parsing JSONL directly (unstable).
   - Prompt/agent hooks on compaction events (not supported).
   - Async hooks for decisions (cannot return decisions).
   - Hooks triggering `/clear` or new sessions (no mechanism).

4. **Recommended Evaluator Implementation:**
   - PreCompact hook reads `transcript_path`, parses conservatively (or rejects binary format).
   - Check `trigger` field to distinguish auto vs manual compaction.
   - Query via `claude -p --resume <session-id> --output-format json` for stable structured analysis.
   - Exit code 2 to block; SessionStart re-injects evaluation results or guidance via additionalContext.
